# Recorded corpus

`spec-<sha>.json` holds traces generated by `harness/run.cjs` and the outcomes the model gives for them, so any implementation can be checked without Lean.

```json
{
  "spec": "14b6d53",        // upstream webmcp commit the model reflects (spec/anchors.json)
  "seed": 7,                // generator seed
  "traces": [
    { "ops":  [ {"op": "register", "name": "c", ...}, {"op": "getTools"}, ... ],
      "want": [ "ok", "tools:c||d|{\"type\":\"object\"}|...", ... ] }
  ]
}
```

`ops` uses the same operations the oracle reads (`WebMCP/Oracle.lean`), and `want[i]` is the outcome of `ops[i]` in the form the harness compares: `ok`, `err:<exception name>`, `result:<string>`, or `tools:` followed by each `Tool` as `name|title|description|inputSchema|outputSchema|annotations`, joined by `;`. A `Tool` whose `source` is another document than the caller ends in `@<document>`.

Operations may name the document they run in with `doc` (an index into the frame tree, `harnessDocs` in `WebMCP/Model.lean`; 0, the top-level document, when absent). `register` and `registerAbortSync` may carry `exposedTo` and `getTools` may carry `fromOrigins`, as lists of `origin:<n>` (origin `n`'s serialization), `path:<n>` (a URL of origin `n` with a path), `invalid` (not a URL) or `insecure` (`http://example.com`); absent means an empty list. Signal `n` belongs to document `n / 3`, and `execute`'s `doc` is the document that calls `executeTool()`, which may differ from the one whose `getTools()` returned the `Tool` (they are then same origin). Older corpora, without these members, parse and run the same way.

A `concurrent` operation starts its `actions` from one script in document `doc` before awaiting any: `register`, `abort`, `getTools` and `execute` (with `signal` `none`, `live` or `aborted`) as above, and `cancel`, which aborts the execution signal of action `target`. Its outcome is `all:` and a JSON array of the actions' outcomes. Each `getTools` action counts as the next `getTools()` call for later `execute`s. Behavior `unregisterSelf` aborts the tool's own registration signal and resolves with its input. Where the spec allows several outcomes for an operation, `want[i]` is `any:` and a JSON array of them.

The current corpus has 1,000 traces and 6,146 operations. 502 traces are generated over the frame tree; the other 498 keep every registration and `getTools()` call in the top-level document, as all traces did before frames were modelled, though 45 of them run an `executeTool()` from the same-origin `<iframe>`. 489 traces have at least one operation outside the top-level document (1,354 such operations). 450 traces have at least one of the 662 `concurrent` operations, and 44 of those operations (in 43 traces) have several allowed outcomes (`any:`). `--record` prints the count of each kind of outcome per operation.

Recording is deterministic: the same model, generator and seed give a byte-identical file. To regenerate after a model change:

```
lake build
node harness/run.cjs --record corpus/spec-<sha>.json 1000 7
```

A change in this file's diff is a change in what the model says the spec requires.
